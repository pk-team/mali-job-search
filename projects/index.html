Demonstrations and learning applications

Projects are instruments for seeing and explaining.

A useful project creates evidence of judgement: a real user problem, a small complete flow, explicit boundaries, failure states, tests, and a clear account of what changed in Mali's understanding.

Possible origins

Job-derived

Make a role's central idea visible without cloning the employer's product.

System-derived

Model one hidden workflow or failure discovered while reconstructing a real project.

Experiment-derived

Compare a new agent, protocol, framework, or method against a stable task.

Community-derived

Build a bounded useful contribution with visible collaboration and users.

Required project explanation

  1. Who is the user and what changes for them?
  2. Which system does this sit inside?
  3. What does the project own, and what does it simulate?
  4. Why was this stack chosen?
  5. Which success, empty, loading, validation, and failure states matter?
  6. What was deliberately omitted?
  7. What evidence shows the central behavior works?
  8. What can Mali explain now that she could not explain before?
Generated code is a teaching artifact. Each project records who implemented it and separately tracks what Mali has reviewed, run, changed, and explained. The repository never turns Codex output into a claim of Mali's authorship or production experience.
